# 查询正确性基准与快照修正演练

版本 v1，2026-11-03。全部输入虚构，适用于无正式表结构阶段。

## 三种互相核对的依据

1. 人工预期：`backend/tests/fixtures/query-cases.json` 明确写出查询和期望人物／证据。输入是 `docs/examples/logical-dataset.json`，预期结果不由生产函数或基准算法生成。
2. 独立基准：`backend/tests/reference_oracle.py` 只处理原始字典，枚举日历月份集合计算交集。它不调用生产 SQL、QueryService、时间规则或证据构建函数。它先和人工预期核对，再用于 500 人差分。
3. 实际实现：SQL 在数据库中过滤、去重和分页；服务生成关系类型、解释和来源证据。比较完整翻页后的结果，不把截断图当成完整结果。

这些测试保证约定样例中的行为一致，不证明真实数据字段契约或生产业务定义已经确认。

初始 17 个手工人物查询，分别以每页 1、3、7、20 人验证，共 68 个分页场景。v0.6 手工增加 7 个共同范围／月数查询，当前共 24 个、96 个分页场景；9 个人物对验证完整证据签名，另有图预算场景验证图截断不影响人物和证据查询。证据签名包括关系类型、共同实体、双方经历键及重叠窗口，并核对来源记录定位。

修改规则时先说明业务依据，再人工更新预期；禁止运行查询实现把“实际输出”直接覆盖成新的期望。

## 固定种子 500 人差分

`backend/tests/differential_data.py` 独立生成 500 人，种子固定为 42，包含同名、双来源、失效记录、偏热门公司、不同任期、未知日期、缺职位和重复经历。它不复用生产演示生成器。

对 30 组实体、来源和时间组合，以及 3 名参考人物各 4 种关系选择，共 42 组查询逐页核对人物集合、排序和去重；核对关系摘要类型及实体。对 3 名参考人物与每名有效人物，比较所有双方证据签名，包括无关系和自身查询。

v0.5 在同一差分数据集新增 4 组多选、旧单值混用、重复选择和空列表场景，当前共 34 组实体查询及 12 组人物关系查询。另用独立 API 测试手工核对 4 组多选结果，验证列表重排／去重后的游标兼容和条件真正变化时的拒绝；两人对比接口对 9 个人物对核对独立证据，并验证交换、同名独立 ID、相同 ID 和失效人物处理。

独立算法以清楚为先，月份集合枚举只用于小规模测试，不进入在线查询。它不模拟真实实体分布，也不是生产压测。

v0.6 另对 3 名参考人物各执行 6 组共同公司、窗口、最短月数与背景组合，共 18 组；每页 7 人遍历完整结果，与独立月份集合核对人物与窗口内完整证据。包含跨年两个月、单侧窗口、当前任职、来源限制，以及候选在另一家公司工作但实际共同经历不在该公司的情况。当前差分共 64 组查询。

人工明确：25 个月门槛不能让 p:08 的两条 24 个月重复记录合计命中；只 p:05 的 35 个月单条证据命中。202101—202112 窗且至少 12 个月时，p:02、p:06、p:08 命中；跨年 202112—202201 且至少两个月只 p:02 命中。带条件证据、摘要和图引用必须一致，原始来源日期保持不变。导出测试核对第二页范围、旧版本／页面不匹配拒绝，以及输入和数据库内容摘要不变。

## v0.7 一位中间人物的独立路径基准

`backend/tests/test_paths.py` 对逻辑样例手工核对：p:01 与同名 p:07 在同公司同期规则下只经 p:06 连接；两段窗口分别为 202001—202112、202201—202212，互不重叠仍是有效经历链。同校规则无链；允许类型混合时中间人物为 p:03、p:06、p:08、p:13，仅专家来源时为双来源的 p:08。p:01 与 p:02 可同时具有直接关系和多条间接链，重复经历保留来源但不重复列中间人物。

独立路径算法枚举原始数据中的全部有效人物，分别调用测试专用的日历月份证据算法核对 A—C、C—B；不调用生产 SQL、PathService 或证据计算函数。固定种子 500 人数据覆盖 3 对端点 × 5 种范围 × 2 种中间来源，共 30 组，核对直接证据、按 ID 排序后的链以及两段全部证据；超过 20 条时核对返回前缀及截断标志。它与原有 64 组列表查询差分分别运行。

另构造只有 A—C—D—B 的三段关系数据，确认不会误当作一位中间人物的路径。检查未知时间同校、失效人物、输入上限、候选耗尽无结果时 limited、恰好达到链数上限而全部检查时仍完整、证据展示截断与搜索完整性独立、事实／时间／核对次数预算及 API 存储故障。

使用真实 SQLite 递归读取触发 VM 预算，验证查询中断、退出清除 progress handler 后普通查询仍成功，真实 SQL 错误不转换为空结果。内容摘要验证路径查询不改数据库。以上是小规模正确性和执行保护验证，不代表生产容量。

## v0.8 R01 候选查询与诊断一致性

新增 `test_scale_benchmark.py`，覆盖固定种子及不同批次大小的数据一致性、逻辑摘要、默认文件保护、已有文件不覆盖、非法参数不留目标文件、计时上下文和错误透传、SQL 观察中断与清理、路径预算不被观察器替换、接口阶段／执行计划实际采集和独立子进程超时。

在 400 人规模样例上，独立日历月份集合枚举完整候选，核对普通／热门端点、同公司／同期／同校、时间窗与来源等 16 组条件，分别与冻结 JOIN 和当前候选实现对比。测试允许更多离线执行预算以穷尽集合，不改变线上请求预算。

在 2000 人固定样例上再对 4 种范围 × 3 种来源 × 4 个端点，共 48 组核对两种 SQL 的完整稳定前缀、排序、去重、端点排除和数据库内容不变；上限加一只用于剩余候选探测，不能宣称前缀是全局全集。原有 500 人独立关系和路径差分继续运行。

两档真实执行的虚构规模报告另核对完整请求的语义摘要；受限路径只对共同返回链核对证据，不将不完整集合当作全量。实测记录、原始 JSON 和复现命令见 [R01 报告](performance/r01-results.md)。

## 快照修正演练

每项测试在独立临时 SQLite 文件中载入 v1，结束 API 生命周期，显式载入 v2，再启动新的 API 生命周期：

| 修正 | 预期变化 |
| --- | --- |
| f:02a 工作经历失效 | p:02 的公司及同期证据消失，同校证据保留 |
| f:02a 的归一公司改为 org:b | 原共同公司关系消失，其他经历不受影响 |
| f:02s 的归一学校改为 school:y | 同校关系消失，公司证据保留 |
| 上游把 f:02a、f:02s 的人物归属改给 p:07 | p:02 失去相应关系，p:07 获得它们，来源经历定位保留；不按同名执行合并 |

每次都验证新数据版本可见、旧分页游标拒绝、查询证据只引用新快照。人物修正测试只消费上游给定的 Fact.person_id，不实现真实来源人物映射表或身份识别。

本轮不支持服务运行中的发布，也不建设增量 Worker。上游未来采用何种变更事件、快照完整性标记及删除机制，仍需要交接评审。

## 运行方法

在 backend 目录使用项目虚拟环境：

```bash
.venv/bin/pytest tests/test_validation.py tests/test_query_baseline.py tests/test_snapshot_rehearsal.py -q
```

在项目根目录执行 `bash scripts/check.sh` 可继续运行全部原有后端测试、类型检查、前端构建及浏览器测试。预检测试通过内容摘要和修改时间核对输入文件与已有数据库未被改变，并确保目标目录不存在时不会创建目录或数据库。
