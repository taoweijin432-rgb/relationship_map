## 复现与原因

用户反馈人物1000、全部共同经历、三跳及四跳出现预算错误。对已部署API按20人分页顺序请求，1至4跳单次HTTP观察分别692.2、845.4、4702.0、2129.1毫秒，前三项返回200，四跳返回503／GRAPH_UNAVAILABLE。当前接口元数据为mysql-live，关系版本real-2a106af85a3330dba3c2-202611。

本机同一冻结真实图可复现四跳拒绝，原生错误码-1005，错误详情为内存水位high watermark(0.800000)。服务器原生错误详情仍需新日志核对。NebulaGraph的内存水位保护会拒绝达到阈值的查询，官方说明见手册。[NebulaGraph 3.8手册](https://docs.nebula-graph.io/3.8.0/pdf/NebulaGraph-EN.pdf)

现有多跳MATCH在每层保留完整前缀人物组合。同校、同专业构成的密集关联会使路径组合快速增长，末尾DISTINCT、排序和LIMIT之前已有大量中间状态。独立SQL事实BFS统计人物1000的1至4跳累计可达51、1619、5173、5696人。分页返回20人时，底层仍需进行范围遍历和排序。

在线人物仓储还把分页探针留到下一次召回处理，活跃候选充足时会重复执行整轮图召回。共同经历模式包含四类物化人物边，遍历和证据读取会覆盖更多关系。多跳请求共用5秒预算，图读取保护为20000返回行、256次RPC。

## 实现

- 普通多跳召回采用原生GO 1 TO N STEPS及终点去重，最终按人物ID排序和游标分页。每跳套用原有实体和同期条件，游标只作用于最终候选，避免中间人物被误排除。
- 带同校前提的同专业继续通过图内同校关系匹配，每层折叠到当前终点。
- 最短链装配每层按终点保留字典序最小前缀。最短路径的前缀也是最短路径，此收敛保留原有最短、稳定并列及简单人物链语义。
- 在线人物分页同时核对额外探针，活跃人物足够时完成一次召回。删除过滤、分页填充和在线人物字段读取贯穿原逻辑。
- 错误提示补充执行时间、图读取或SQL执行量等预算原因。图执行拒绝记录原生错误、查询指纹、调用数、返回行数和耗时。诊断计时覆盖GraphClient.execute及MySQLPeople.read。

修复覆盖查询执行、分页和诊断。关系数据及源配置沿用已发布版本，人物展示在线回MySQL。当前多跳请求预算为5秒，生产图读取预算为20000行及256次RPC。
