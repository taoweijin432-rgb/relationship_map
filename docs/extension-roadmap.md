## 当前基础

已实现人物／实体查询、多选、来源及时间筛选、直接关系与证据、两人对比、履历时间轴、公司／学校专题、本机条件保存、当前页 JSON／CSV 与局部图 PNG，以及最多一位中间人物的有界连接链。路径条件和结果目前不进入保存与导出。

本机 FastAPI、SQLAlchemy、Vue 和 G6 保留；默认 SQL，v0.9 增加 MySQL 对照，v0.10 建立图环境，v0.11 完成 [模拟图投影与候选接入](graph-query-validation.md)。图辅助暂未显示加速收益，保持显式选择；真实数据与 Linux 环境仍待验证。身份统一与实体归一仍由上游负责，既有与新增检查均不是生产容量证明。

## A：现在可用虚构数据推进

| 编号 | 方向 | 可交付内容 | 需要明确的边界 |
| --- | --- | --- | --- |
| R01 | 已完成 v0.8：模拟规模验证与查询诊断 | 固定种子 1 万／10 万人物、热门实体和长履历分布；阶段、SQL 计划、受限原因、响应大小及浏览器记录；有界候选 SQL 优化 | 结果见报告，仅本机虚构数据，不能推算百万级生产容量；长履历大响应待后续设计 |
| R02 | 路径保存与证据报告 | 保存端点、规则与预算；恢复后重新搜索；导出选中连接链或本次已展示链的逐段证据与来源 | 明确保存的是条件还是保留版本的历史结果；截断与预算必须随报告保留，不将报告写成真实社交关系 |
| R03 | 图探索操作 | 人物定位、固定节点、隐藏／恢复显示、布局切换、撤销一次展开与返回前一查询中心 | 显示过滤不改变列表完整性；明确撤销范围、累计节点／边上限及请求取消行为 |
| R04 | 候选人物工作集 | 跨查询收集、移除、分组、备注，批量发起对比或导出 | 本地保存可先验证；以稳定 ID 重新校验失效与版本，不自行合并同名人物，不默认为团队共享 |
| R05 | 多人背景对比 | 小名单的共同公司／学校矩阵、履历并排和证据钻取 | 先限制人数，按需查询人物对；不预计算全库两两关系，不把相同职位认作人际关系 |
| R06 | 更丰富的筛选语义 | 必须同时满足多个公司、排除实体、任期状态、关系类型组合、仅查直接或仅查间接等 | 每项先定义公司／职位同条经历、不同经历、多实体 AND／OR、空值与否定的含义；数据缺失不直接解释为“从未任职” |
| R07 | 查询命中解释 | 列表解释命中的公司／职位／时间，突出实际匹配经历，清晰区分背景命中、共同证据及其他履历 | 解释由后端产生，与实际过滤和图引用一致，不由前端推断 |
| R08 | 数据预检可视化 | 展示已有只读预检的错误、提示、引用定位与统计；与上游核对问题清单 | 逻辑样例阶段只展示约定格式；不自动纠正日期、实体或人物身份；正式表质量统计依赖字段映射 |

## 建议选取顺序

R01 已完成一轮规模与诊断。尚无真实数据时，后续优先考虑 R02（路径使用闭环）、R03（图探索操作），必要时继续复测 R01。若业务重点是整理候选人，可将 R04 与 R07 提前。

新表一旦到位，优先转向 R09 和 R10，再根据数据交付契约推进 R11。R15—R18 随公司实际使用与部署要求确定。R19—R21 应各自立项明确目标，不默认全部纳入首版。

R01 已实施，R09 已做候选来源评估，其余候选没有自动启动。后续选定方向时在主架构文档记录决定与验收证据，再更新本清单状态。
