# MySQL／NebulaGraph 技术验证计划

日期：2026-11-03。状态：v0.9 完成本机 MySQL 阶段，v0.10 建立图环境，v0.11 完成模拟投影与可选图候选接入；并发负载与真实数据阶段待实施。本文不确定生产选型、上游 DDL 或容量。结果见 [MySQL 报告](performance/mysql-results.md)、[图环境记录](nebula-environment.md)和 [图业务验收](graph-query-validation.md)。

用户先确认可使用本地 MySQL、暂无图数据库、Linux 测试服务器目前不可用，随后请求建立本地图数据库环境。现已使用独立 Compose 项目建立 NebulaGraph；现有 MySQL 与 Canal 保留。以下分阶段内容保留为验收依据，环境建立不等于图仓储、投影或负载测试已完成。

## 可以现在验证什么

正式数据尚未交付，但已有稳定业务契约、独立正确性基准和 R01 规模数据，可以在真实数据库进程中验证 SQL 方言、索引、驱动、连接池、图投影、路径候选、来源证据及故障行为。真实数据到位后仍需重做字段映射、分布分析和目标规模验证。

实验比较三种后端：SQLite 参照、仅 MySQL、MySQL＋NebulaGraph。只有证据支持图数据库带来收益时，才将相应查询切换到图；人物筛选、稳定分页和权威经历证据先保留在 SQL 侧。不为显示关系图而强制访问图数据库。

## 已核查的本机条件

2026-11-03 通过 `docker info`、`docker ps`、`mysql --version`、`sysctl` 和 `lsof` 只读核查：

| 项目 | 观察结果 | 对实验的影响 |
| --- | --- | --- |
| 宿主机 | ARM64，16 GiB 内存 | 镜像需核对原生架构；模拟其他架构时单独标记结果 |
| Docker | CLI 29.4.0；引擎报告 aarch64、10 CPU、约 7.82 GiB 内存 | 已具备容器入口；不能认为资源足够同时运行任意规模集群 |
| 现有 MySQL | 本机 127.0.0.1:3306；后续授权连接确认服务端 9.7.1，默认 utf8mb4_0900_ai_ci | 实验表显式二进制排序；只操作新建实验库，不读取业务表 |
| 其他现有容器 | Canal 容器正在运行 | 不停止、重建或复用其数据卷；资源观察需记录其影响 |

后续需要容器时建议使用独立 Compose 项目、网络、命名卷和未占用端口，仅绑定本机。本轮按用户选择直接复用现有 MySQL 服务的新建实验库。MySQL 与图先分阶段运行；组合验证前再确认剩余资源。不得直接运行官方示例的完整多副本集群后，把本机争用结果作为选型结论。

公司已有版本和 Linux 测试环境时优先匹配。暂无约束时，MySQL 8.4 LTS 可作为候选；NebulaGraph 需先确认社区／开发者／企业版本、服务端、Python SDK 和 ARM64 镜像兼容组合，再锁定具体版本、镜像摘要及配置，不使用浮动 latest。不同版本及版本类别不能混作同一套验证结论。

官方 [NebulaGraph 3.8 资源说明](https://docs.nebula-graph.io/3.8.0/4.deployment-and-installation/1.resource-preparations/) 提供 ARM 容器运行支持信息，但仍须核对所选具体镜像和本机引擎。SDK 按 [官方兼容矩阵](https://github.com/vesoft-inc/nebula-python#compatibility-matrix) 选择；MySQL 候选版本参考 [官方 8.4 LTS 页面](https://dev.mysql.com/downloads/mysql/8.4.html)。本机容器验证通过不等于目标 Linux 部署环境已通过。

## 第一阶段：接通 MySQL 并核对语义

1. 创建专用实验库和账号，导入前先运行已有逻辑校验。使用固定种子的同一份规范化逻辑快照，记录数据版本、基准月份、内容摘要、有效／失效记录数；分别载入 SQLite 和 MySQL。不能为每个引擎各生成一套略有不同的数据。
2. 在 `infrastructure` 增加 MySQL 查询／路径仓储，遵守现有 `services/ports.py` 协议。`app.py` 目前直接构造 SQLite 仓储，需要增加明确的存储配置与装配入口；默认本地 SQLite 启动和重置行为保持兼容。API、Service、Domain 继续复用，不在路由增加数据库分支。
3. 继续采用同步 SQLAlchemy 和同步路由，驱动安装于 `backend/.venv` 并更新锁文件。先验证连接池上限、获取连接等待、语句超时、失败回收，再根据结果决定是否值得改异步。
4. 显式处理字符串 ID 的大小写、排序及游标顺序；核对别名查找、LIKE 转义、NULL、年月换算、当前任职、区间端点、同条经历关联和 DISTINCT 分页。不得把 SQLite 的 VM 步保护直接当作 MySQL 的执行预算。
5. 小型人工样例与独立 500 人基准先通过，再导入 R01 的 1 万／10 万人物数据。核对人物全集、全部分页、关系类型及证据引用；预算受限结果单独核对已返回证据和完整性标志，不能要求不同引擎在不同时限下返回完全相同的部分集合。
6. 用实际 SQL 和执行计划评估候选索引，记录估算／实际行数、循环、排序及耗时。`EXPLAIN ANALYZE` 会实际执行语句，仅对隔离实验查询运行，参考 [MySQL 官方说明](https://dev.mysql.com/doc/refman/8.4/en/explain.html)。索引只形成实验读模型，不冻结生产 DDL。

通过条件：业务语义无差异、完整查询分页无遗漏重复、错误可区分、超时后连接可复用，默认演示库与现有服务未改变。失败不能降格成空结果。

## 第二阶段：NebulaGraph 图投影与逐段证据

1. 用同一逻辑快照建立独立实验图空间。以稳定人物／实体 ID 建立顶点，工作／教育事实关联保留经历标识、时间、状态和来源定位。重复任职必须可区分；不把多条事实压成一条无来源的边，也不预计算全库人物两两关系。
2. 先做少量事实的写入、读取与删除核对，确认 VID、重复边标识方案、索引可用时机和客户端解码。逻辑 A—共同实体—C—共同实体—B 是两段业务关系，不能机械写成图的两跳。
3. 图仓储先提供有界候选人物／连接链；依据仍由 SQL 经历与共享 Domain 规则复核。图中的时间过滤只能做等价过滤或不会漏掉有效结果的候选预筛；职位始终作为经历条件，不能独立拼接出人际关系。
4. 不改变至多一位中间人物的业务范围。核对候选排序、去重、来源、有效性和共同窗口；候选、展开、事实、证据、时间均有预算。查询末尾加 LIMIT 不等于底层展开工作有界，需检查实际执行计划和热门实体扫描量。
5. 小型全量基准核对所有候选、关系和证据；规模实验同时比较 MySQL 单独执行与图辅助执行的延迟、扫描、内存和装配成本。图拓扑命中不是最终证据，受限搜索不能声称全局无路径。
6. SQL 与图的版本分别标识，只有完整导入并对账的相同版本才启用组合查询。演练图滞后、投影失败、断连、超时和重启；版本不匹配须明确拒绝，或在已有实现且条件相同的 SQL 回退路径上重新执行并标明，不能静默混用或伪装为空结果。SQL 复核能去除旧图假阳性，但无法找回图未写入的新关系，不能代替版本一致性检查。

通过条件：逐段证据可定位，完整结果与独立基准一致，所有部分结果均有正确限制说明；证明图的收益或明确保留 MySQL 实现，不以“已经安装”作为必须采用图数据库的理由。

## 第三阶段：真实 HTTP 与受控并发

先做单并发实际 HTTP，再以 5／10 并发作为实验档位逐步观察；这是测试参数，不是生产目标。按资源情况延长运行和重复次数，记录请求数、错误率、超时率、P50／P95／P99 的样本量、连接等待、数据库执行、证据装配、序列化、响应大小及宿主机／容器资源。图区分依赖故障、预算耗尽和业务无结果。

复用 R01 的普通／热门公司学校、多条件、空结果、深游标、长履历、直接及间接路径场景。冷热状态分别说明，不将首次查询叫作清空所有缓存的冷启动。每个实验记录版本、镜像摘要、资源限制、配置、数据摘要、索引、SQL／图计划和原始结果；本机后台负载及虚拟化影响不能遗漏。

R01 的长履历对比约 18.25 MB 响应作为已知风险继续保留：更换数据库不会自动解决证据装配与传输量。单独验证该场景；若实施分页或摘要，应另行定义契约并回归，不为性能数字静默裁剪。

## 快照修正、交付与后续

用隔离版本分别演练经历失效、实体归一纠正和上游人物映射变更。沿用停服务／切换完整快照约定，确认 SQL、图、证据和游标一致变化；本阶段不顺带接入现有 Canal，也不建设未经来源契约定义的生产 CDC。

交付应包括：锁定的环境与启动／停止说明、模拟数据导入与对账命令、MySQL 适配器、图投影及候选适配器、跨引擎正确性测试、故障与预算测试、可复现的 HTTP 负载记录及选型结论。只有实际接入完成后，才更新主方案和 AGENTS 中的“尚未接入”状态。

模拟 SQL／图接入范围见验收记录，当前图辅助未显示性能收益；真实数据投影、HTTP 并发负载和生产账号部署仍待实施。公司目标数据库版本／版本类别、正式结构、真实分布、并发与时效、生产恢复和运维目标仍待确认。没有真实数据时仍不能证明百万级生产容量、最终索引或增量同步可靠性。
