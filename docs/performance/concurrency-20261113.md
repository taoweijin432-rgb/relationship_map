# 本地人物关系查询并发测试

测试日期为2026年11月13日，报告核对更新于2026年11月16日，时间统一采用Asia/Shanghai。业务代码基线为`3a9c48f38f14648d2af5093de628abbf59829064`，对应`qa-20261113-02`。本轮产出为压测材料、性能报告和主方案修订。

当前配置下，连续四跳查询触发图内存保护，8／16配置并发时还出现大量RPC名额等待失败。独立轻量补测的三跳在1／2／4并发下成功，一跳多并发仍有偶发会话失败。两并发认证专项已复现重复会话ID及相应执行终止，需先修正会话使用方式和多跳内存开销，再验收稳定并发容量。

## 环境与数据

- 本机macOS ARM64，10个CPU逻辑核心、16GiB内存。Docker虚拟机内存约7.82GiB，同时运行既有Canal容器。
- 使用独立HTTP API进程，绑定`127.0.0.1:18088`，单Uvicorn worker，按正常应用入口加载既有真实发布。
- NebulaGraph 3.8.0，graphd限额1 CPU／1GiB，storaged限额2 CPU／2GiB，metad限额0.5 CPU／512MiB。
- 数据版本为`real-2a106af85a3330dba3c2-202611`，6525位专家、12801个实体、25239条事实。
- 本地采用`snapshot`人物展示模式，关系查询经过真实本地Nebula RPC，背景及证据经过发布SQLite。
- 服务器2026年11月13日核验时采用`mysql-live`和6711位专家的新发布。在线MySQL、SSH隧道、Nginx、公网网络以及服务器混部资源的成本，需在对应环境单独测量。

## 测试方法

主测试于17:17:07至17:26:12完成，覆盖1、2、4、8、16配置并发与5类场景，共25组。关系场景固定为人物`p:expert:1000`、全部共同经历、每页20人，测试1／3／4跳首屏。搜索轮换空关键词、真实姓名前缀和业务编号，混合场景按上述四类请求各25%安排。

使用HTTP/1.1 keepalive和闭环并发请求任务，每组至少运行20秒并完成至少20个样本，最长发起窗口90秒。每组共用40请求/秒的发起上限，错误后等待250毫秒，再发起后续请求。HTTP客户端超时20秒，连接上限24，阶段结束等待已进入的请求返回。成功吞吐以成功样本数除以包含收尾的阶段实际耗时计算。

配置并发表示闭环并发请求任务数。限速及快速失败会使实际在途请求少于配置值，表中同时列出实际采样峰值。候选搜索受40请求/秒上限约束，实际在途峰值为1至2，搜索容量上限仍需更高负载测量。

所有成功响应均检查真实数据模式、固定数据版本，以及结果人物、连接链、图节点与边的稳定摘要。多跳另检查连接端点、跳数、人物唯一性与画布完整性。摘要比较使用固定样本的单请求基准，独立业务正确性沿用已有SQL对照记录。

P50／P95仅由成功请求计算，失败率使用全部请求。不同场景依次执行，阶段间隔1秒，图服务的内存及会话状态由整个负载序列共享。

## 资源与错误定位

本轮采集140份资源快照，约每4秒记录一次Docker指标和API进程RSS，包含启动与查询阶段。graphd采样峰值为1012MiB／1GiB，即98.87%，CPU峰值约104.75%，接近1 CPU限额。storaged采样内存峰值约1.044GiB／2GiB，CPU峰值约116.19%。这些为间隔采样值，瞬时峰值可能更高。

API及图服务日志均出现80%内存水位拒绝。四跳连续负载会使图服务拒绝后续元数据校验及轻量查询，因此主测试的一跳、三跳错误同时包含共享图服务状态的影响。容器状态检查显示graphd与storaged持续运行，RestartCount为0，graphd的OOM及OOM-kill计数均为0。

应用侧每个图客户端通过4个信号量名额控制同时执行的RPC，等待名额上限约100毫秒。8／16配置并发时大量返回`GRAPH_BUSY`，一跳成功吞吐约10请求/秒，增加配置并发后成功吞吐趋于持平。

## 会话诊断

采用两并发、4000次独立认证和已授权图空间元数据读取，耗时约11.94秒。认证后保留2毫秒重叠窗口，读取后释放会话和连接。实际取得3975个唯一会话ID，出现25次重复ID，3999次读取成功、1次返回执行终止。第597轮两个认证线程获得同一会话ID，一个读取成功，另一个返回`Execution had been killed`。材料仅保留会话ID摘要。

NebulaGraph v3.8.0的Meta实现采用微秒时间戳生成会话ID，Graph端把会话登记到本地缓存。官方PR #5916将ID生成改为随机值以避免并发创建冲突。本地重复ID与同会话上的执行终止已经实测复现，主测试中各类会话失败的完整因果分布仍需进一步核对。[v3.8.0 Meta源码](https://raw.githubusercontent.com/vesoft-inc/nebula/v3.8.0/src/meta/processors/session/SessionManagerProcessor.cpp)、[v3.8.0 Graph会话管理源码](https://raw.githubusercontent.com/vesoft-inc/nebula/v3.8.0/src/graph/session/GraphSessionManager.cpp)、[官方会话ID修复PR](https://github.com/vesoft-inc/nebula/pull/5916)

本项目当前每个图RPC均创建并释放一次会话，重复认证增加了会话创建次数。后续应验证串行创建、跨RPC独占复用的会话池及请求剩余超时处理，并专项覆盖失败回收、版本切换、并发读取和进程退出。图服务修补版本的选择需核对实际镜像所含提交。
