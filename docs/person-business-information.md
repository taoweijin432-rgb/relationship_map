# 人物业务附属信息需求与存放建议

版本 v1.1 ｜2026-11-06 ｜架构 v0.22 ｜当前目标图模型 uuid-relations-v5

用户进一步明确需要业务编号、工作信息和教育信息。姓名不入图的要求继续有效；它不等于禁止一切有用途的业务属性。此前 person 只留 source_system 是最小模型选择，不应表述成用户要求人物业务信息一律禁止。

用户已要求重新整理并落实字段，当前以 [完整定义 v2.0](graph-ddl.md) 为准：业务编号、职位、教育属性和经历组键已纳入独立图 DDL／样例，应用和真实源适配未实施。下表保留选取依据；位置说明如与新完整定义不同，以完整定义为准。

## 推荐信息范围

| 信息 | 用途 | 已有来源 | 存放建议 |
| --- | --- | --- | --- |
| 业务编号 serial_number | 业务定位、姓名不可见时显示编号 | experts.serial_number；resume 按已确认对应结构 | 本版作为 person 属性；按来源区分，不当跨库统一人物键 |
| 来源及来源人物键 | 来源筛选、回查、避免数字 ID 碰撞 | 来源主表类别与 id | 已有 person.source_system 与 VID，不重复增加完整人物行 |
| 工作经历的公司、起止月、当前状态 | 同公司、同期与履历展示 | 工作原表＋有效公司归一 | 公司节点＋worked_at 已承载结构；每次任职单独保留 |
| 每次任职的职位 | 展示或筛选某公司某职位 | 同工作行 position_title | 本版作为 worked_at.position_title，不放人物节点的单一职位属性 |
| 工作内容 | 完整经历详情 | 工作行 work_description | SQL 按需读取，不默认把长文本写图 |
| 教育学校、专业和时间 | 同校、同专业及履历 | 教育原表＋有效学校／专业归一 | school／major 节点＋studied_at／studied_major 已承载结构 |
| 每次教育的学历与统招信息 | 履历展示、后续教育条件筛选 | 同教育行 education_level／is_regular_enrollment | 本版作为两类教育边的对应属性，不放专业节点 |
| 经历来源与证据引用 | 解释关系、回查、定位修正 | graph_edge_mapping 与原经历 id | 事实 Rank 与人物边的左右事实 Rank 已具备，不因显示字段增加而取消 |
| 有效状态 | 排除删除人物、经历、归一映射或实体 | 原表 deleted_at、标准表／映射 is_deleted、边映射 deleted_at | 构建过滤；当前不可变图只保留有效事实，不要求每节点再存删除标志 |
| 来源更新时间与投影版本 | 展示数据新旧、追溯变化 | 原行 updated_at、标准实体 source_updated_at、发布清单 | 原行时间回 SQL；图整体投影／快照／基准月已有控制节点，不能把两者混为一个时间 |
| 日期完整性 | 区分未知、当前任职和已知任期 | 原行 start_date／end_date／is_employed | NULL 与当前状态规则保持；不能用无关系或未毕业解释未知 |
| 地区、工作年限、人物学历摘要 | 按业务需要展示或筛选 | 原人物 country／province／city／work_years／education | 可选，默认 SQL；不把主表学历摘要替代具体教育经历 |

## 必须保持的边界

- 一个业务编号只在已确认的来源命名空间中使用；不据编号相同或姓名相同合并专家与简历。编号仍能回连个人，图、接口与展示需要相应权限。
- 工作公司、职位、时间来自同一条工作经历；人物可以多次任职，不把多个公司和职位塞成互不关联的数组。
- 学校、专业、学历、时间绑定同一条教育行。后续“同校同专业”组合必须核对双方各自的同条教育关联，不能拼接不同教育经历。
- 姓名、联系方式及个人长文本继续只从 SQL 按展示权限读取，不回写图。未知或缺失不自动补齐。
- 项目、证书、语言、技能等不属于当前关系查询的必需范围。虽然部分原表已有项目和证书字段，是否增加能力需独立业务需求，不因字段存在就纳入图。

本版已落实业务编号、工作职位与教育学历的字段定义；来源、证据、状态、时间与版本属于必须完整保留的基础信息，其中已有能力继续复用。新增个人附属属性不改变人物身份／实体归一由上游负责的分工。
