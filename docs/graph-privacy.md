# 图中人物属性与姓名展示边界

版本 v1.3 ｜2026-11-06 ｜架构 v0.24 ｜当前模型 uuid-relations-v5

用户明确：person 节点不能存入姓名，姓名必须回 MySQL 查询后展示。此前 person.name 的显示冗余设计撤销。用户随后明确需要业务编号、工作信息和教育信息；这些应按具体用途设计，姓名禁入不应扩大解释为禁止一切业务附属属性。当前 DDL 已增加业务编号并将工作／教育字段绑定经历，位置与范围见 [业务附属信息](person-business-information.md)。

## 1 当前字段边界

| 对象 | 当前允许内容 | 不允许的补充 |
| --- | --- | --- |
| 人物图键 | p:expert:<id>／p:resume:<id> | 不含姓名、手机号、邮箱、姓名拼音或用姓名构造的键 |
| person 属性 | source_system 与 serial_number，均 STRING NOT NULL | 不写 name、显示姓名、姓名缩写、脱敏姓名、人物详情 JSON 或自由文本等旁路 |
| 人物关系／经历边 | 标准实体引用、经历事实引用、月份和关系计算所需属性 | 不复制人物姓名、联系方式或完整简历文本到边属性 |
| 公司／学校／专业节点 | 当前 DDL 的标准实体 name | 不把人物姓名混入实体属性以绕开 person 限制 |
| 控制节点 | 投影版本、完整快照摘要、基准月与构建状态 | 不用包含姓名的投影名称或备注；整体快照摘要不作为姓名检索索引 |

本版人物 TAG 的完整定义是 `CREATE TAG person(source_system STRING NOT NULL, serial_number STRING NOT NULL)`；VID 仍是图键，不是重复属性。基础 DDL 为 uuid-facts-v3.ngql，人物关系边定义继续复用 person-relations-v3.ngql，完整模型标识是 uuid-relations-v5；不能把旧带 name 的模型直接改版本标志当迁移完成。

所有人物显示信息以 MySQL 为准。图导入器后续应采用属性白名单构造 person 数据，不能把原人物整行透传，也不能仅把 name 删掉后继续存其余未审核列。人物关系计算不需要姓名，四类关系与证据规则保持不变。

## 2 查询与展示的目标链路

1. 人物姓名定位在 MySQL 完成，返回稳定人物标识；姓名搜索内容不发给 NebulaGraph。
2. 图只接收人物／实体 VID 和查询条件，返回人物标识、关系类型、共同实体和事实 Rank。
3. API 将图结果中的人物 ID 按来源分组、去重后，向 MySQL 批量查询允许展示的姓名；不能每个节点单独查询。
4. 在应用层按 VID 装配显示 DTO，前端图和列表展示该 DTO；姓名不回写图，也不把完整带姓名 DTO 当成新的图写入负载。
5. 权限不足或 SQL 查询失败须保持明确状态，不能拿旧图中的姓名作为回退，也不能伪装成人物没有关系。导出必须沿用相同的人物显示权限范围。

当前仍没有生产身份认证与字段权限系统，本轮不声称上述授权链路已经实现。新模型 API／前端适配时，应同时验证批量回查、同名不同人、来源分离、SQL 故障、权限拒绝，以及图写入和日志没有复制姓名。API 的显示响应仍可包含有权限展示的姓名；“图中不存姓名”不等于界面不显示姓名。

## 3 去标识的边界

不存姓名不等于完全匿名。图中的来源主键、任职／教育和人物关系仍能回连到个人，因此图访问、备份、日志和导出也需要相应权限控制。当前保留来源型 VID 以满足已确认的回查设计，不擅自新增身份桥接或改为用姓名散列的标识；是否采用独立不透明人物键需另行评估。

## 4 旧模型与本轮范围

v0.24 已按本边界在新 SQL／图虚构快照完成全流程迁移：新 person TAG 只有 source_system／serial_number，写入采用允许属性白名单；列表、图 DTO、对比、证据与导出的人物姓名均从配套 SQL 读取，姓名定位请求不发送至图。相关人物和路径不调用旧 SQL／Python 关系引擎。专项检查及运行对象见 [迁移记录](uuid-graph-migration.md)。这不等于已完成生产登录、字段权限、审计、真实隐私数据验证或历史副本清理。

以下段落保留 v0.22 独立 DDL 轮次的状态：

旧 v0.16 模拟投影 writer 仍包含 person.name：graph_projection.py 和 projection_source_graph.py 均有旧字段；旧演示图也可能保留虚构姓名。它们仅代表历史模拟实现，不能用于按本隐私规则接入真实人物。当前没有真实姓名入图的验证或生产接入。

本轮新增无姓名基础 DDL、修订两个固定图验证脚本及文档，使用全新临时空间验证；没有更新旧 writer、访问／清理既有图空间、切换服务、访问 Supabase 或修改 MySQL。旧空间若未来需清理，应单独列明目标和保留要求，不能无差别 DROP 或称“所有历史副本已清理”。

实际验收见 [最新业务与隐私验证](graph-business-fields-validation.md)。新模型还需完整源适配、SQL 姓名回查、API／前端和成对发布；只改 DDL 不等于这些功能已迁移。
