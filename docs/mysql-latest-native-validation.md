## 范围与结论

用户授权本地创建最新版测试表，并要求模拟数据履历可信、关系分布均衡及覆盖多跳。本轮在本机独立MySQL 8.4.13容器创建最新版5表58列和既有8张原表，共13表228列，实际执行一致性初始化、binlog复制协议、事务持久化、微批构建与本机NebulaGraph 3.8.0发布。graph_edge_mapping由实验写入端模拟同事维护，本项目采集账号只有SELECT及复制读取权限，UPDATE被数据库拒绝。

三次独立运行全部通过。最终版本使用具名虚构机构、实际专业名称及行业相关岗位，最终脚本摘要与记录匹配。三个MySQL容器及15个临时图空间／15个账号均已回收，激活指针退役。保留SQL导出、初始来源快照、履历、手工用例与每轮回读记录，实验目录不可作为现有查询服务的可用发布源。

## 两跳关系验证

第一组三人关系由明确原工作经历形成。

```mermaid
flowchart LR
    A[陈亦舟] ---|澜桥软件科技，2016至2018同期| B[林知夏]
    B ---|远岚信息技术，2020至2023同期| C[周景行]
```

陈亦舟与周景行没有直接关系，林知夏是中间人物。两个同期区间分别成立，没有要求三人同时任职。其余三组分别为公司→学校、学校→专业、专业→公司。

11项人工预期通过现有MaterializedReader.paths入口逐项执行正反向查询，追加同期关系筛选及中间人物来源排除。独立原表参照不调用生产投影、时间或关系函数，另在真实图中按8个起点分块核对整组人物的所有两跳三元组。

- 27607个“起点—中间人物—终点”三元组完整一致。
- 覆盖4681个人物端点对，其中2809对没有直接关系。
- 查询范围沿用最多一位中间人物，三条边链保留为范围外反例。
- SQL专项确认学校7和专业8必须来自同一教育行，专家9的两行无法拼接，简历9可匹配。

## 实现与兼容

- 新增update/mysql_source.py，使用锁定的mysql-replication 1.0.16读取真实复制协议。初始化由独立协调连接持短全局读锁，读取连接建立RR视图和日志基线后释放锁，存量读取保持同一视图。
- 读取器按完整Xid事务交付RowChange前后镜像，事件及提交位置在UpdateStore持久化成功后确认。source whitelist筛选、事务预算、源实例／列指纹、日志位置检查均在边界执行，DDL和不支持的事件类型阻断。当前要求ROW、FULL镜像／列元数据、无事务压缩及局部JSON选项，已实测MySQL 8.4.13及文件位置恢复。
- 新增numeric-authoritative-v1，直接消费graph_edge_mapping，取消该模式对逻辑name_mapping的依赖。来源id保留为Rank，原numeric-v1及文件回放继续兼容。已删除旧映射与活跃替代记录可并存，多个活跃目标占同一来源槽位仍显式拒绝，等待正式业务粒度契约。
- 新增infra/mysql/schema/file-mapping-v1.sql、权威来源示例契约、scripts/mysql_update_dataset.py及scripts/mysql_update_lab.py。
- 新增18项离线协议／适配回归，更新专项合计72项通过，完整后端500项通过／240项按环境跳过。后端Ruff lint、Mypy及新增文件格式检查通过，脚本Ruff检查通过。
