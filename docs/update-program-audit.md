## 当前结论

已完成代码审计、修复和本机NebulaGraph 3.8.0真实运行。全量、目标纠正、名称映射DELETE、新增人物及跨月微批的图结果符合独立人工预期，实际GUEST账号可读且写入被拒绝。

当前可验收范围是文件快照／完整事务回放到独立SQL快照及真实图发布。MySQL一致性快照读取器、实时CDC传输、自动周期调度及数字模式查询API仍待实现或接入；此次没有连接MySQL，也未验证真实Binlog连续性。

## 发现与修复

| 优先级 | 原行为与影响 | 本轮修复 | 代码位置 |
| --- | --- | --- | --- |
| P1 | 未配置物理表的行事件被忽略，整个事务仍可确认并推进位点，可能遗漏表更名后的数据 | 返回UNEXPECTED_TABLE，完整事务回滚并暂停采集及发布 | update/store.py capture |
| P1 | 回放解析、事务协议、值序列化或单行字节预算错误发生在迭代器取值时，未进入原采集异常边界，状态仍为streaming | 统一捕获迭代器及持久化的协议错误，保留最后完整提交位置并暂停，保持已发布指针 | update/service.py capture |
| P1 | 管理员回读与GRANT成功后立即允许发布，尚未确认新只读账号的认证和权限传播 | 独立GUEST连接核对完成标记，最长60秒重试传播；失败保持候选状态并阻断激活 | update/target.py verify_reader |
| P2 | bootstrap的月份和行数预算检查部分位于创建状态文件之后，输入被拒绝也会占用该初始化路径 | CLI在创建状态前核对月份及预算，校验失败后路径可直接重试 | update/cli.py _execute |
| P2 | 旧候选重试时复用较大的已冻结范围，可能超过本次调小的max_transactions | 返回BATCH_RANGE_LIMIT，要求使用足以容纳既有完整范围的预算 | update/store.py claim |
| P2 | 图构建失败、收据尚未返回时，候选目录缺少新空间名，资源难以追溯 | 创建外部空间前记录build-resource.json，成功发布时纳入摘要核对 | update/target.py、artifacts.py |

新增14项回归情景，更新专项由40项增至54项。前两类缺陷的4项回归在修复前实际失败，修复后全部通过。来源协议错误包含非法JSON、不完整事务、超长事务行、非有限数值及过长整数编码；确认丢失仍可按原位点重放。

采集器应先按配置白名单筛选相关行事件，再组装完整已提交事务。event_count是交付给核心的相关事件总数；没有相关行的已提交事务可交付空事件及连续提交位置。DDL控制事件继续交付并暂停。核心不再自行忽略未知表，避免掩盖契约漂移。

## 本机真实运行

先通过正式CLI执行bootstrap和publish，完成6节点／6事实／4人物关系的原生图发布。随后运行可重复的隔离验证脚本，直接调用实际UpdateProgram、SQLite状态及NebulaTarget，图写入、nGQL计算、账号授权和回读均使用本机真实服务。

```bash
backend/.venv/bin/python scripts/update_program_lab.py \
  --output data/update-program-audit/my-new-run
```

脚本要求新目录，使用固定虚构输入。输出包含私有状态和核对报告，结束回收仅由本次创建意图及账号文件标识的空间和账号，并将active.json退役为retired-active.json。不得用已回收的验证目录作为查询服务来源。
